# 中文提交信息生成 Skill

## 功能说明

自动分析 Git 变更，生成符合项目风格的中文提交信息。

## 使用方式

```bash
/commit-cn              # 分析当前变更，生成提交信息
/commit-cn -m "自定义"  # 使用自定义信息（跳过分析）
```

## 提交信息风格

根据项目历史提交分析，采用以下风格：
- **简洁直接**：一句话说明做了什么（10-20 字）
- **中文描述**：使用中文，不使用英文术语（除非必要）
- **功能导向**：说明功能变化，不说技术细节

**示例**：
```
无线充电只放不充功能增加
更稳定版本
功率控制逻辑优化
修复 ADC 采样异常问题
```

## 工作流程

### 1. 分析变更
```bash
git status              # 查看变更文件
git diff --staged       # 查看已暂存的变更
git diff                # 查看未暂存的变更
```

### 2. 识别变更类型
- **新功能**：新增文件或新增函数 → "XXX功能增加"
- **优化改进**：修改现有逻辑 → "XXX优化" 或 "更稳定版本"
- **问题修复**：修复 bug → "修复XXX问题"
- **代码重构**：重构代码结构 → "XXX重构"
- **文档更新**：仅修改文档 → "更新XXX文档"

### 3. 生成提交信息
根据变更类型和影响范围，生成简洁的中文描述。

**优先级规则**：
- 如果有新功能 → 以新功能为主题
- 如果只是优化 → "更稳定版本" 或 "XXX优化"
- 如果修复问题 → "修复XXX问题"

### 4. 执行提交
```bash
git add [文件]                    # 暂存变更
git commit -m "提交信息"          # 提交
```

## 提交信息模板

### 新功能
```
{功能名称}功能增加
{模块名称}功能实现
```

### 优化改进
```
更稳定版本
{模块名称}逻辑优化
{功能名称}性能优化
```

### 问题修复
```
修复{问题描述}问题
修复{模块名称}异常
```

### 代码重构
```
{模块名称}代码重构
优化代码结构
```

### 文档更新
```
更新{文档类型}文档
完善项目文档
```

## 注意事项

1. **保持简洁**：10-20 字，不超过一行
2. **避免技术术语**：用"采样"不用"ADC sampling"
3. **说明结果**：说"功能增加"不说"添加了代码"
4. **符合历史风格**：参考 `git log` 中的提交风格

## 特殊场景

### 多个变更
如果一次提交包含多个不相关的变更，建议拆分提交：
```bash
git add file1.c
git commit -m "功能A增加"

git add file2.c
git commit -m "功能B优化"
```

### 紧急修复
```
紧急修复{问题}
热修复{问题}
```

### 版本发布
```
发布 v{版本号}
稳定版本发布
```
