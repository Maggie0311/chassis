# 功率控制扭矩反解卡顿修复

> 对应提交：`0bd6e8c 功率控制修好`
> 涉及文件：[applications/chassis_fun/suprCap3/fun_powerCtrl.c](../../applications/chassis_fun/suprCap3/fun_powerCtrl.c)

## 一、问题现象

底盘在 **边陀螺（旋转）边前进/平移，且功率受限** 时，出现非常明显的卡顿、顿挫；
而 **只直行** 或 **只陀螺** 时一切正常，丝滑无卡顿。

## 二、功率模型与扭矩反解

### 2.1 单电机功率模型

每个轮向电机的电功率由 RLS 在线辨识，模型为（[fun_powerCtrl.c:645-648](../../applications/chassis_fun/suprCap3/fun_powerCtrl.c#L645-L648)）：

$$P = \theta_0\,\tau^2 + \frac{V}{9.55}\,\tau + \theta_1|V| + \frac{\theta_2}{4}$$

| 项 | 物理含义 |
|---|---|
| $\dfrac{V}{9.55}\,\tau$ | 机械功率（$\omega\tau$，$\omega=V/9.55$） |
| $\theta_0\,\tau^2$ | 铜损 $I^2R$（扭矩 ∝ 电流，故正比于 $\tau^2$），$\theta_0$ 是**小系数** |
| $\theta_1\,\|V\|$ | 与转速相关的损耗（铁损等），用绝对值 |
| $\theta_2/4$ | 固定静态损耗 |

其中 $\tau$ 为扭矩（带符号）、$V$ 为转速 rpm（带符号）。

### 2.2 扭矩反解：一元二次方程求根

功率受限时反过来：已知转速 $|V|$、给定目标功率 $P_{target}$（`allo_power_set`，被功率限制压小），求应输出的扭矩 $\tau$。

反解代入 $|V|$，得到关于 $\tau$ 的二次方程：

$$\theta_0\,\tau^2 + \frac{|V|}{9.55}\,\tau + \Big(\theta_1|V| + \frac{\theta_2}{4} - P_{target}\Big) = 0$$

判别式：

$$\Delta = \Big(\frac{|V|}{9.55}\Big)^2 - 4\,\theta_0\Big(\theta_1|V| + \frac{\theta_2}{4} - P_{target}\Big)$$

两个根：

$$\tau_{+} = \frac{-|V|/9.55 + \sqrt{\Delta}}{2\theta_0},\qquad \tau_{-} = \frac{-|V|/9.55 - \sqrt{\Delta}}{2\theta_0}$$

---

## 三、电动根 vs 回馈根（核心概念）

二次方程之所以有 **两个根**，是因为功率模型是关于 $\tau$ 的 **抛物线**。给定同一个目标功率 $P_{target}$ 画一条水平线，会与抛物线交于 **两点**，对应电机 **两种不同的工作状态**。

### 3.1 电动根 $\tau_{+}$（"+"根）

- 扭矩方向 **与转速方向相同**；
- 电机 **主动做功驱动负载**（电能 → 机械能），即正常的"使劲推着车走"；
- 扭矩绝对值 **较小**：因为机械功率 $\tau\omega$ 已为正且较大，不需要太大的扭矩即可达到给定功率。

当 $P_{target}$ 较小、$|V|$ 不算特别小时，$\sqrt{\Delta}\approx |V|/9.55$，于是：

$$\tau_{+} \approx \frac{-|V|/9.55 + |V|/9.55}{2\theta_0} \approx 0$$

**目标功率小 → 输出扭矩小**，符合功率限制的直觉。

### 3.2 回馈根 $\tau_{-}$（"-"根）

- 扭矩方向 **与转速方向相反**；
- 电机 **被负载拖动 / 制动**（机械能 → 电能），处于 **发电/回馈制动** 状态（下坡、减速、被外力拖着转）；
- 扭矩绝对值 **很大**：因为机械功率 $\tau\omega$ 为负，要靠巨大的铜损 $\theta_0\tau^2$ 把数值"凑"回到目标功率。

同样条件下：

$$\tau_{-} \approx \frac{-|V|/9.55 - |V|/9.55}{2\theta_0} = \frac{-|V|/9.55}{\theta_0}$$

由于 $\theta_0$ 是小数，$\tau_{-}$ **数值爆炸**成很大的负值。这就是新代码注释里写的：

> *避免"-"(回馈)分支在小 $P_{target}$ 时 $\tau \approx |V|/(9.55\cdot\theta_0)$ 导致的数值爆炸*

### 3.3 形象类比

要电机消耗 50 W 功率，有两种方式：

| 方式 | 状态 | 扭矩 | 现象 |
|---|---|---|---|
| A（电动根） | 正向使劲推车 | 小 | 合理，正常行驶 |
| B（回馈根） | 反向刹车 | 巨大 | "用大电流猛踩刹车 + 绕组狂发热"凑出 50 W |

---

## 四、那回馈根到底有什么用？为什么这里可以全用电动根？

### 4.1 回馈根的"本来用途"

回馈根本是为 **主动能量回收 / 精确制动** 场景设计的——例如电动汽车下坡时，控制器需要知道"以多大的制动扭矩去回收能量，同时把回馈功率控制在电池能接受的预算内"。此时 $\tau_{-}$ 给出的是 **有方向语义的制动扭矩**。

### 4.2 为什么在本项目可以舍弃

在 RoboMaster 底盘这个场景里，回馈根 **既无用又有害**，原因有三：

1. **没有能量回收需求**：超电的充放电由另一套 `SCap_PowerCtrl` 独立管理，轮向功率控制器不需要"规划一个巨大的制动扭矩来回收能量"。

2. **`fabsf` 抹掉了方向语义**（关键）。反解后这一段 [fun_powerCtrl.c:795-802](../../applications/chassis_fun/suprCap3/fun_powerCtrl.c#L795-L802)：

   ```c
   temp_run = fabsf(allo_tor_set);          // ← 取绝对值，正/负方向信息丢失
   if (Current_pid.Output >= 0)
       Current_pid.Output =  temp_run / K_IC2Tor;
   else
       Current_pid.Output = -temp_run / K_IC2Tor;   // 方向由速度环符号重新赋
   ```

   两个根算出来的扭矩，**方向都被丢弃、只用大小，再由 `Current_pid.Output` 的符号重新决定方向**。既然只用大小，回馈根算出的"巨大负值"被 `fabsf` 变成巨大正值，被当成正向大电流送出——**完全违背了"这是制动扭矩"的语义**。换句话说，回馈根在这套代码框架里从一开始就是语义错误的，不只是数值爆炸。

3. **数值爆炸**：如 3.2，$\tau_{-}\approx -|V|/(9.55\theta_0)$，小系数 $\theta_0$ 导致爆炸。

因此：**只保留电动根**，扭矩大小随 $P_{target}$ 单调变化（小功率→小扭矩），方向交给速度环输出符号，已经覆盖底盘行驶/旋转的全部需求。

---

## 五、Bug 根因

旧代码（修改前）根据 **转速方向与速度环期望扭矩方向是否同号** 在两个根之间切换：

```c
if (SIGN_F(V_now) * SIGN_F(Speed_pid.Output) >= 0) {
    // 同号 → 电动根 "+"
    allo_tor_set = (-|V|/9.55 + sqrt(Δ)) / (2θ₀);
} else {
    // 异号 → 回馈根 "-"  ← 在 P_target 小时爆炸
    allo_tor_set = (-|V|/9.55 - sqrt(Δ)) / (2θ₀);
}
temp_run = fabsf(allo_tor_set);   // 爆炸的大值取绝对值
Current_pid.Output = ±temp_run / K_IC2Tor;   // 当成正向大电流送出
```

于是 **功率限制越严（$P_{target}$ 越小），异号轮子反解出的扭矩越大**，正好与功率限制的目的相反：
巨大电流 → 实际功率飙升 → 保护更狠地压低 $P_{target}$ → 回馈根爆得更大 → 循环。
输出在"几乎为 0"和"猛冲"之间剧烈跳变，**表现为底盘顿挫/卡顿**。

## 六、为什么"陀螺 + 前进"才会触发

关键在选根的判断条件 `SIGN_F(V_now) * SIGN_F(Speed_pid.Output)`：

- **纯直行**：四轮转速方向与维持该速度所需扭矩方向一致 → 同号 → 走电动根，正常。
- **纯陀螺**：左右轮速度反向，但每轮"当前转向"与"维持旋转所需扭矩"仍同向 → 主要走电动根。
- **陀螺 + 前进叠加**：平动与转动合成后，**总有些轮子处于被陀螺分量"拖拽"的工作点**——当前转速 $V_{now}$ 方向与速度环要求它输出的扭矩方向反号（电机被动进入发电/回馈区）。一旦异号就掉进 **回馈根**，再叠加功率受限，立刻爆炸。

所以"只直行、只陀螺都顺，一组合就卡"的根本原因：**只有组合运动才会让轮子稳定地落在异号（回馈）工作点**，从而稳定触发爆炸的回馈根。

## 七、修复方案

[fun_powerCtrl.c:786-794](../../applications/chassis_fun/suprCap3/fun_powerCtrl.c#L786-L794)，三处改动：

```c
// 轮向电机功率反解
//   始终用 "+"(电动) 分支计算扭矩大小, 方向沿用旧 Current_pid.Output 的符号
//   避免 "-"(回馈) 分支在小 P_target 时 τ ≈ |V|/(9.55*θ₀) 导致的数值爆炸
{
    float disc = SQUARE(V_now / 9.55f) -
                 4 * theta[0] * (theta[1] * fabsf(V_now) + theta[2]/4.f - allo_power_set);
    if (disc < 0.f) disc = 0.f;          // ① 保护 sqrtf，极小负判别式截断
    allo_tor_set = (-fabsf(V_now)/9.55f + sqrtf(disc)) / (2 * theta[0]);   // ② 永远只取电动根
}
temp_run = fabsf(allo_tor_set);
if (Current_pid.Output >= 0)                                              // ③ 方向交给速度环符号
    Current_pid.Output =  temp_run / K_IC2Tor;
else
    Current_pid.Output = -temp_run / K_IC2Tor;
```

1. **永远只取电动根 $\tau_{+}$**：它在小 $P_{target}$ 时给出接近 0 的小扭矩，功率限制才真正生效，杜绝"越限越冲"。
2. **`disc < 0 → 0` 截断**：避免 `sqrtf` 收到极小负值出 NaN 这种偶发尖刺。
3. **方向完全由 `Current_pid.Output` 符号决定**：反正两根都要被 `fabsf` 抹方向，直接用不会爆炸的根取大小即可。

## 八、关联改动

- [fun_powerCtrl.c:738-739](../../applications/chassis_fun/suprCap3/fun_powerCtrl.c#L738-L739)：注释掉 `if (Power_Set.run_power < 0) PowerCtrl.power_allo_flag = 0;`。旧逻辑一遇总轮向功率为负就粗暴关掉功率分配、直接用原始电流环输出，导致功率控制时有时无，本身就是顿挫源；新反解能正确处理小/负功率后，不再需要这层回避。
- [fun_powerCtrl.c:524-527](../../applications/chassis_fun/suprCap3/fun_powerCtrl.c#L524-L527)：`get_chassis_max_power` 中功率缓冲（`PowerBuff`）项注释掉，简化功率上限计算（与本卡顿主线无关）。

## 九、一句话总结

> 旧的二次方程求根用「转速/扭矩同号与否」在电动根与回馈根间切换，而回馈根在功率受限（$P_{target}$ 小）时会因 $\theta_0$ 很小而数值爆炸，再被 `fabsf` 当成正向大电流输出，使功率限制失效并引发"猛冲—保护"振荡；陀螺 + 前进叠加恰好把轮子推到异号的回馈工作点才暴露问题。修复 = 固定用不会爆炸的电动根取扭矩大小，方向交给速度环符号。
